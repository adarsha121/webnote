    🐧 The Linux File System, Explained

    One tree to rule them all. Everything in Linux, from your photos to your keyboard to your running programs, lives somewhere inside a single tree that starts at /.

    This guide walks through every top-level directory you see on a typical Ubuntu system (the *.usr-is-merged, snap, swap.img and cdrom entries are the giveaway), ordered from most relevant to everyday use to least.

    1. 🌳 / (root) is everything

    Windows vs Linux

    On Windows, storage is split into separate drives:

    C:\          D:\          E:\ (USB)

    On Linux, there are no drive letters. There is one single tree, and its starting point (the trunk) is /, called root.

    /
├── home
├── etc
├── usr
├── var
└── ...everything else

    A second hard disk, a USB (PenDrive), a network share: all of them get attached (mounted) onto a branch of this one tree. For example, a USB stick might appear at /media/yourname/MYUSB.

    Think of Linux as one giant tree. Windows is more like a row of separate cupboards (C:, D:, E:). In Linux, new cupboards are not placed beside the tree; they are grafted onto a branch.

    ⚠️ Don't confuse these two

    Name Meaning
    / The root of the entire file system (the trunk)
    /root The home directory of the root user (the admin account)

    📝 Golden rules

    • Everything is a file: documents, folders, devices, even running processes are represented as files.
    • Case-sensitive: Notes.txt and notes.txt are different files.
    • Forward slash / separates folders (not \).
    • Paths starting with / are absolute (/home/sam/notes.txt); others are relative to where you are.

    3. 🏠 /home: your personal space

    What it is: Every normal user gets their own folder here. This is where you live: documents, downloads, pictures, and your personal app settings.

    /home
├── sam/
│   ├── Desktop/
│   ├── Documents/
│   ├── Downloads/
│   ├── Pictures/
│   ├── Music/
│   ├── Videos/
│   ├── .bashrc
│   ├── .config/
│   └── .ssh/
└── priya/

    🧠 Analogy

    /home is an apartment building. Each user has their own locked apartment (/home/sam, /home/priya). Sam can't casually wander into Priya's flat.

    Key points

    • Your folder can be written as ~ (tilde). cd ~ takes you home. ~ is shorthand for /home/yourname.
    • Hidden files start with a dot (.), for example .bashrc, .config. They hold your personal app settings. Use ls -a to see them.

    Notable subfolders

    Path Purpose
    ~/Documents, ~/Downloads, ~/Pictures ... Standard user folders
    ~/.config Per-user app settings (modern apps)
    ~/.local/share Per-user app data (themes, trash, etc.)
    ~/.cache Per-user cache; safe to delete
    ~/.ssh Your SSH keys (keep private!)
    ~/.bashrc Your shell customisations (aliases, prompt)

    💡 Pro tip

    Since all your personal data and settings live here, backing up /home backs up "you". Many people put /home on a separate partition so reinstalling Linux doesn't wipe their files.

    4. ⚙️ /bin: essential commands

    What it is: Short for binaries: the programs (commands) everyone needs, even in emergencies. Things like ls, cp, mv, cat, bash, rm.

    $ which ls
/usr/bin/ls

$ ls -l /bin
lrwxrwxrwx 1 root root 7 ... /bin -> usr/bin

    🧠 Analogy

    /bin is the basic toolbox in your kitchen drawer: knife, spoon, can opener. Without them you can't do the basics.

    🔗 Modern note: it's a shortcut now

    On modern Ubuntu, /bin is just a symbolic link (shortcut) pointing to /usr/bin. Old systems kept them separate; new ones merged them (see section 24). So /bin/ls and /usr/bin/ls are literally the same file.

    5. 🛠️ /etc: configuration files

    What it is: The settings centre of the whole system. Almost every service and program stores its system-wide config here, mostly as plain text files you can read and edit.

    Fun fact: "etc" originally meant et cetera (miscellaneous), but today think of it as "Editable Text Configuration".

    🧠 Analogy

    /etc is the Settings app of Linux. Instead of clicking toggles, you edit text files.

    Important files and folders

    Path What it does
    /etc/passwd List of user accounts (no actual passwords despite the name)
    /etc/shadow Encrypted password hashes (root-only)
    /etc/group User groups
    /etc/sudoers Who may use sudo
    /etc/fstab Which disks to mount at boot
    /etc/hostname The computer's name
    /etc/hosts Local name → IP address mapping
    /etc/apt/ Package manager settings (repositories in sources.list.d)
    /etc/ssh/ SSH server and client settings
    /etc/systemd/ Service manager configuration
    /etc/network/, /etc/netplan/ Network configuration
    /etc/cron.d/, /etc/crontab Scheduled tasks
    /etc/os-release Info about your distro and version
    /etc/default/ Default settings for various services
    /etc/environment System-wide environment variables

    Example

    $ cat /etc/os-release
PRETTY_NAME="Ubuntu 24.04 LTS"
...
$ cat /etc/hostname
my-laptop

    ⚠️ Careful

    Edit with sudo, and make a backup first: sudo cp /etc/fstab /etc/fstab.bak. A typo in the wrong file can stop your system from booting.

    6. 📦 /usr: installed software and resources

    What it is: Despite the name, it does not mean "user". It stands for Unix System Resources. This is the largest directory, holding most installed programs, libraries, and documentation. It is mostly read-only during normal use.

    🧠 Analogy

    /usr is the city's main warehouse. Whenever you install an app, its parts get shelved here.

    Subdirectories

    Path Contents
    /usr/bin Most user commands (python3, git, gcc, ls...)
    /usr/sbin Admin commands (useradd, iptables...)
    /usr/lib Libraries used by programs in /usr/bin
    /usr/lib64 64-bit libraries (some systems)
    /usr/local Software you install manually; package manager won't touch it
    /usr/share Architecture-independent data: icons, docs, fonts, man pages, locale files
    /usr/include C/C++ header files (for developers)
    /usr/src Source code (e.g., Linux kernel headers)
    /usr/games Old-school games

    /usr/local spotlight

    If you compile a program from source (./configure && make && sudo make install), it normally lands in /usr/local/bin. This keeps your hand-installed stuff separate from what apt manages.

    /usr/local/bin/mytool     ← your custom stuff
/usr/bin/git              ← installed by apt

    /usr/share spotlight

    $ ls /usr/share
applications  doc  fonts  icons  man  themes  zoneinfo ...

    This is where the man pages (/usr/share/man) and desktop icons live.

    7. 📜 /var: variable data

    What it is: var = variable. Files here grow and change constantly while the system runs: logs, caches, mail, databases, and queued jobs.

    🧠 Analogy

    If /etc is the rulebook, /var is the diary and mailroom: it records what has been happening.

    Subdirectories

    Path Contents
    /var/log System and app logs. First stop when troubleshooting
    /var/cache Cached data (e.g. downloaded .deb packages in /var/cache/apt)
    /var/lib Persistent app state (databases, package manager data, Docker, snap data)
    /var/spool Queued items (print jobs, cron jobs, mail)
    /var/tmp Temp files that survive reboots (unlike /tmp)
    /var/mail User mailboxes
    /var/www Often the default website folder for Apache/Nginx
    /var/run Symlink to /run
    /var/crash Crash reports
    /var/backups Automatic backups of key system files

    Example: read logs

    sudo tail -f /var/log/syslog      # watch system messages live
sudo less /var/log/auth.log       # who logged in? failed sudo attempts?
journalctl -xe                    # systemd's journal (stored in /var/log/journal)

    💡 Tip

    If your disk is mysteriously full, check /var/log and /var/cache first: sudo du -sh /var/* | sort -h.

    8. 🗑️ /tmp: temporary files

    What it is: A scratch space any user or program can write to. Cleared on reboot (or periodically).

    🧠 Analogy

    /tmp is scratch paper on your desk. Great for rough work, but don't put anything you care about on it. Someone will bin it.

    echo "draft idea" > /tmp/idea.txt

    Key points

    • Anyone can write here, but each user can only delete their own files (the "sticky bit", shown as drwxrwxrwt).
    • Installers, browsers, and compilers often drop temporary files here.
    • For temp files that must survive a reboot, use /var/tmp.

    9. 🔌 /dev: devices as files

    What it is: Hardware is represented as files. You don't "open a driver"; you read from and write to a file.

    🧠 Analogy

    /dev is the wall of plug sockets. Every device (disk, keyboard, webcam) has its own socket, and you talk to it by using the file.

    Common entries

    Path Meaning
    /dev/sda, /dev/sda1 First SATA/SCSI disk and its first partition
    /dev/nvme0n1, /dev/nvme0n1p1 First NVMe SSD and its first partition
    /dev/tty* Terminals
    /dev/null Black hole: anything written vanishes
    /dev/zero Endless stream of zero bytes
    /dev/random, /dev/urandom Random number generators
    /dev/loop* Loop devices (mount image files as disks; used heavily by Snap)
    /dev/pts/ Pseudo-terminals (terminal windows)
    /dev/shm Shared memory (RAM-backed)
    /dev/disk/by-uuid/ Disks listed by their unique ID

    Fun examples

    ls /dev/sd*                      # list SATA disks
command_that_is_noisy > /dev/null   # throw away output
head -c 16 /dev/urandom | xxd       # 16 random bytes

    10. 📊 /proc: the live process window

    What it is: A virtual file system. It doesn't exist on disk; the kernel generates it in memory. It exposes live information about running processes and the system.

    🧠 Analogy

    /proc is the hospital monitor beside the patient: heart rate, temperature, live and always changing. Nothing is stored; it just shows what's happening now.

    Key entries

    Path What you'll find
    /proc/cpuinfo CPU details
    /proc/meminfo RAM usage
    /proc/uptime How long the system has been running
    /proc/version Kernel version
    /proc/mounts Currently mounted file systems
    /proc/<PID>/ A folder for each running process (e.g. /proc/1234/)
    /proc/self/ The process looking at it (a handy shortcut) 
    cat /proc/cpuinfo | grep "model name"
cat /proc/meminfo | head -3
ls /proc/self/

    Tools like top, ps, and free mostly just read from here!

    11. 🎛️ /sys: kernel and hardware panel

    What it is: Another virtual file system, a structured view of devices, drivers, and kernel settings. Where /proc is a bit of a historical grab-bag, /sys is the tidy, organised version for hardware.

    🧠 Analogy

    /sys is the dashboard with switches and dials. You can read gauges and flip some switches.

    Example: change screen brightness

    cat /sys/class/backlight/*/brightness
echo 50 | sudo tee /sys/class/backlight/*/brightness

    Key subfolders

    Path Contents
    /sys/class/ Devices grouped by type (net, block, power_supply, backlight)
    /sys/devices/ The real hardware tree
    /sys/block/ Block devices (disks)
    /sys/power/ Power management (suspend, hibernate)
    /sys/module/ Loaded kernel modules

    /proc vs /sys at a glance

    /proc /sys
    Mostly processes + some system info Mostly hardware, drivers, kernel config
    Older, less organised Newer, tidy structure

    12. 🚀 /boot: startup files

    What it is: Everything the computer needs to start Linux: the kernel, the initial RAM disk, and the bootloader (GRUB).

    🧠 Analogy

    /boot is the ignition key and starter motor. Without it the car won't start, no matter how good the engine is.

    What's inside

    File/Folder Purpose
    vmlinuz-<version> The compressed Linux kernel
    initrd.img-<version> Initial RAM disk, a tiny temporary system used during early boot
    grub/ GRUB bootloader config (grub.cfg)
    config-<version> Kernel build config
    System.map-<version> Kernel symbol table
    efi/ EFI System Partition mount (on UEFI machines) 
    ls /boot
uname -r        # shows the kernel version currently running

    ⚠️ Warning

    Don't delete files here unless you're sure. Removing the running kernel can leave you unable to boot. Use sudo apt autoremove to clean old kernels safely.

    13. 🧰 /sbin: system administration commands

    What it is: System binaries: commands meant for administrators, such as fdisk, mkfs, reboot, iptables, ip. Many need sudo.

    🧠 Analogy

    /bin is the kitchen toolbox for everyone; /sbin is the manager's toolbox: shutting the shop, rewiring the electrics, rearranging storage.

    On modern Ubuntu, /sbin is a symlink to /usr/sbin.

    sudo fdisk -l          # list disk partitions
sudo reboot            # restart the machine

    14. 📚 /lib and /lib64: shared libraries

    What it is: Libraries are reusable code that many programs share, similar to .dll files on Windows. Instead of each program bundling its own copy, they all borrow from here.

    🧠 Analogy

    Libraries are the shared pantry. Every recipe (program) needs flour and salt (common code); keeping one pantry is smarter than one per cook.

    Path Purpose
    /lib Shared libraries (.so files = "shared objects") needed by /bin and /sbin
    /lib64 64-bit libraries, including the dynamic loader ld-linux-x86-64.so.2
    /lib/modules/<kernel-version>/ Kernel modules (drivers)
    /lib/firmware/ Firmware blobs for hardware (Wi-Fi cards, GPUs)
    /lib/systemd/ systemd unit files and helpers

    On modern Ubuntu, /lib → /usr/lib and /lib64 → /usr/lib64 (symlinks).

    ldd /bin/ls            # shows which libraries "ls" depends on

    15. 🧳 /opt: optional software

    What it is: Home for self-contained, third-party software that doesn't follow the standard layout, for example Google Chrome, Zoom, or some commercial tools. Each gets its own subfolder.

    🧠 Analogy

    /opt is the guest suite. Visitors (big third-party apps) bring their own furniture and live in their own self-contained room, instead of scattering things around your house.

    /opt
├── google/chrome/
├── zoom/
└── some-vendor-app/
    ├── bin/
    ├── lib/
    └── config/

    Rule of thumb: - Installed via apt → goes to /usr - Compiled by you → /usr/local - Big bundled third-party app → /opt

    16. 💾 /mnt and /media: mount points

    Remember: Linux has no D: drive. Mounting means "attach this storage to a folder in the tree". Two folders exist for this.

    /media (automatic)

    Used when you plug in a USB stick, SD card, or external drive. The desktop mounts it automatically.

    /media/sam/MY_USB/

    /mnt (manual)

    A temporary manual mount point for admins.

    sudo mount /dev/sdb1 /mnt          # attach a disk
ls /mnt                            # browse it
sudo umount /mnt                   # detach safely

    🧠 Analogy

    Think of your computer as a ship with docking ports. /media is the auto-docking port (the ship docks by itself). /mnt is the manual docking port where the captain docks things by hand.

    /mnt vs /media

    /media /mnt
    Mounted by Desktop automatically You, manually
    Typical use USB, SD, DVDs Temporary admin mounts, extra disks
    Folder structure /media/<user>/<label> Whatever you choose

    (On WSL, Windows drives show up as /mnt/c, /mnt/d.)

    17. 👑 /root: the administrator's home

    What it is: The home directory of the root user (the all-powerful superuser). It's kept outside /home so it stays available even if /home is on another disk that fails to mount.

    🧠 Analogy

    If /home/sam is Sam's apartment, /root is the principal's private office. Locked to normal users.

    ls /root            # Permission denied
sudo ls /root       # works

    Remember: /root ≠ /. One is the superuser's home; the other is the trunk of the entire tree.

    18. ⏱️ /run: runtime data

    What it is: A RAM-based (tmpfs) folder holding information about the system since it booted: PID files, sockets, lock files. It is wiped on every reboot.

    🧠 Analogy

    /run is the sticky notes on today's whiteboard. They're useful now, thrown away at night (reboot).

    Path Contents
    /run/user/<UID> Per-user runtime data (e.g., /run/user/1000)
    /run/lock Lock files
    /run/systemd systemd runtime state
    /run/*.pid Process ID files
    /run/*.sock Communication sockets

    /var/run is just a symlink to /run.

    19. 🏪 /srv: served data

    What it is: Data that your machine serves to others over the network: websites (HTTP), FTP files, Git repos, etc. It's often empty on desktop installs.

    🧠 Analogy

    /srv is the shop counter. What's placed here is meant for customers (other computers), not for you.

    /srv/www/        ← a website
/srv/ftp/        ← files for FTP clients
/srv/git/        ← git repositories

    (Some tools use /var/www instead; both conventions exist.)

    20. 📦 /snap: Snap packages

    What it is: Ubuntu's Snap package system stores its software here. Each snap is a sealed, self-contained bundle (mounted as a compressed read-only image), so apps carry their own dependencies.

    🧠 Analogy

    If apt is buying loose ingredients, Snap is a sealed lunchbox: everything the meal needs is packed inside and doesn't mix with other food.

    /snap
├── bin/              ← symlinks to snap commands
├── core22/ ...       ← base runtime snaps
├── firefox/
└── snapd/

    snap list              # see installed snaps
sudo snap install vlc  # install one

    Snap data lives in /var/lib/snapd, and per-user data in ~/snap. Because each snap is mounted as a loop device, you'll see many /dev/loopN entries.

    21. 💤 /swap.img: swap file

    What it is: A file acting as extra memory. When RAM fills up, Linux moves less-used data here (disk-based "overflow memory"). Ubuntu creates it by default instead of a separate swap partition.

    🧠 Analogy

    RAM is your desk; swap is the cupboard beside it. When the desk is full, you move papers into the cupboard. It works, but fetching from it is slower.

    swapon --show          # see active swap
free -h                # RAM and swap usage
ls -lh /swap.img       # its size

    ⚠️ Don't delete it casually. Disable it first with sudo swapoff /swap.img and remove its line from /etc/fstab.

    22. 🧯 /lost+found: recovery bin

    What it is: A special folder created by the ext4 file system. When a disk check (fsck) after a crash finds file fragments with no name or parent folder, it drops them here.

    🧠 Analogy

    The lost-property office of your disk. Normally empty; if something lands here, it's a rescued orphan.

    • You'll find one on each ext4 partition's top level.
    • Only root can read it. Normally you just leave it alone.

    23. 💿 /cdrom: legacy optical mount

    What it is: A mount point for CD/DVD drives from the days of installer discs. Usually empty on modern systems; Ubuntu creates it as part of the install process. Today, optical media are mounted under /media/<user>/ instead.

    24. 🧩 The *.usr-is-merged entries explained

    You have bin.usr-is-merged, lib.usr-is-merged, and sbin.usr-is-merged. These look odd, but they have a simple story.

    History

    Originally:

    /bin   → essential commands for boot/rescue
/usr/bin → everything else

    That split dates back to the 1970s, when disks were tiny and /usr lived on a separate disk. Today it's pointless.

    The "usr merge"

    Modern distros merged them: /bin, /sbin, /lib, /lib64 are now symlinks into /usr.

    /bin   → usr/bin
/sbin  → usr/sbin
/lib   → usr/lib
/lib64 → usr/lib64

    What the *.usr-is-merged folders are

    They're empty marker directories left by a Debian/Ubuntu package that records "this system has completed the usr-merge". They hold nothing; treat them as "✅ merged" stickers. Leave them alone.

    🧠 Analogy

    Two filing cabinets (/bin and /usr/bin) were merged into one. The old cabinet's drawer fronts now carry a note: "see the other cabinet". That's the symlink. The *.usr-is-merged folders are the "merge complete" stamps.

    25. 🧭 Putting it all together: a command's journey

    What actually happens when you type ls or open Firefox?

    1. Power on: firmware starts the bootloader in /boot (GRUB), which loads the kernel (vmlinuz) and initrd.img.
    2. The kernel mounts /, reads /etc/fstab, and attaches other disks.
    3. systemd reads its configuration from /etc/systemd and starts services. Their runtime state goes in /run and logs go to /var/log.
    4. Devices appear in /dev; the kernel exposes info in /proc and /sys.
    5. You log in, and your shell starts in /home/you, with settings from ~/.bashrc.
    6. You type ls. The shell searches the folders in your $PATH (/usr/local/bin, /usr/bin, ...) and finds /usr/bin/ls.
    7. ls borrows shared code from /usr/lib, then lists the files you asked for.
    echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin

    26. 🔍 Handy commands to explore

    ls /                      # list the top level
tree -L 1 /               # tree view, one level deep (install: sudo apt install tree)
pwd                       # where am I?
cd /                      # jump to root
cd ~                      # jump home
df -h                     # disk usage per mounted file system
du -sh /var/*             # which folders are biggest?
lsblk                     # block devices and their mount points
mount | column -t         # everything currently mounted
findmnt                   # mounts as a tree
file /bin                 # confirms it's a symlink
ls -l /                   # shows symlinks like bin -> usr/bin
man hier                  # official manual for the file system hierarchy

    🎯 Summary / TL;DR

    • Linux has one tree starting at /; extra storage is mounted onto branches.
    • You live in /home.
    • Settings live in /etc.
    • Programs live in /usr (with /bin, /sbin, /lib as shortcuts into it).
    • Changing data and logs live in /var; scratch work in /tmp.
    • Hardware = files in /dev; live system info in /proc and /sys.
    • Startup files are in /boot.
    • Extras: /opt (third-party), /mnt + /media (mounting), /snap (Snap apps), /swap.img (overflow memory), /lost+found (recovered fragments).

    💬 "In Linux, everything is a file, and every file has a place."
