    SciPy & SymPy: A Practical Guide for Physicists and Mathematicians

    A hands-on reference for doing numerical (SciPy) and symbolic (SymPy) mathematics in Python. It is a guide, not documentation: for each topic you get the one or two functions you will actually use, the few parameters worth tweaking, and a worked example with real output.

    All outputs below were produced with Python 3.12, NumPy 2.5, SciPy 1.18, SymPy 1.14. Random examples use a fixed seed, but your last digits may differ slightly across versions and platforms.

    Part 0 – Setup

    0.1 Installation and imports

    pip install numpy scipy sympy matplotlib

    Conventions used throughout this guide:

    import numpy as np
import sympy as sp          # or: from sympy import *  (fine for notebooks, avoid in scripts)
from scipy import constants, optimize, integrate, interpolate, linalg, fft, special, stats

np.set_printoptions(precision=4, suppress=True)   # tidier array output

    SciPy is organised into sub-packages that you import separately (scipy.integrate, scipy.optimize, ...). Importing bare import scipy does not give you all of them.

    0.2 SciPy vs SymPy: which one, when?

    SciPy SymPy
    Works with Floating-point numbers and arrays Symbols and exact expressions
    Answer looks like 0.7071067811865476 sqrt(2)/2
    Speed Fast (compiled code) Slow (pure Python, symbolic)
    Best for Data, simulation, large systems, anything with no closed form Derivations, exact results, checking by hand, generating formulas
    Fails when Problem is ill-conditioned or poorly scaled Expression explodes, or no closed form exists

    A typical physics workflow uses both: derive an equation of motion or integral symbolically with SymPy, convert it to a fast function with lambdify, then solve or fit it numerically with SciPy. See Section 21.

    Part I – SciPy (numerical)

    1. Physical constants and units

    scipy.constants contains the CODATA values (recent SciPy versions follow the 2022 set) and common unit conversion factors, all in SI units.

    1.1 Commonly used constants

    from scipy import constants as C

print(C.c)      # speed of light, m/s
print(C.h)      # Planck constant, J s
print(C.hbar)   # reduced Planck constant
print(C.k)      # Boltzmann constant, J/K
print(C.G)      # gravitational constant
print(C.e)      # elementary charge, C
print(C.N_A)    # Avogadro constant

    299792458.0
6.62607015e-34
1.0545718176461565e-34
1.380649e-23
6.6743e-11
1.602176634e-19
6.02214076e+23

    Other handy names: C.epsilon_0, C.mu_0, C.m_e, C.m_p, C.m_n, C.R (gas constant), C.sigma (Stefan-Boltzmann), C.alpha (fine-structure constant), C.g (standard gravity), C.golden (golden ratio).

    1.2 The full database: value, unit, uncertainty

    Every constant lives in physical_constants as a (value, unit, uncertainty) tuple.

    print(C.physical_constants['electron mass'])
print(C.value('Planck constant'), C.unit('Planck constant'))

    (9.1093837139e-31, 'kg', 2.8e-40)
6.62607015e-34 J Hz^-1

    Can't remember the exact key? Search for it:

    print(C.find('Bohr')[:3])

    ['Bohr magneton', 'Bohr magneton in Hz/T', 'Bohr magneton in K/T']

    1.3 Unit conversion factors

    Conversion factors multiply a quantity into SI.

    print(C.eV)       # 1 eV in joules
print(C.atm)      # 1 atm in pascals
print(C.mile)     # 1 mile in metres
print(C.degree)   # 1 degree in radians
print(C.hour)     # 1 hour in seconds

    1.602176634e-19

    print(C.convert_temperature(100, 'Celsius', 'Kelvin'))   # 373.15
print(C.lambda2nu(500e-9))     # wavelength (m) -> frequency (Hz)

    373.15
599584916000000.0

    Example – energy of a 500 nm photon in eV:

    E = C.h * C.c / 500e-9 / C.eV
print(E)    # ≈ 2.48 eV

    Tip: C.physical_constants is a plain dict, so a quick for name in C.physical_constants: ... plus a string test is a fine way to browse. For rigorous work, always carry the uncertainty (third tuple entry) along.

    2. Curve fitting and regression

    Fitting is where constants lead naturally: you have measured data, and you want the parameters of a model (a spring constant, a decay time, a coupling strength). We go from the simplest model to a fully custom one.

    All examples in this section share this synthetic data (noise added to known "true" parameters so you can check the fit):

    rng = np.random.default_rng(0)
x = np.linspace(0, 10, 30)
y_lin  = 2.5*x + 1.0 + rng.normal(0, 0.5, x.size)           # true: slope 2.5, intercept 1
y_quad = 0.5*x**2 - 3*x + 2 + rng.normal(0, 1, x.size)      # true: 0.5, -3, 2

    2.1 Linear fit

    scipy.stats.linregress is the quickest route and gives you uncertainties and correlation for free.

    from scipy import stats
r = stats.linregress(x, y_lin)
print(r.slope, r.intercept)
print("R^2 =", r.rvalue**2, "  slope std-err =", r.stderr)

    2.495195730208406 0.9632780990786465
R^2 = 0.9970608712452762   slope std-err = 0.025602010549719674

    For a plain polynomial of degree 1, np.polyfit(x, y, 1) returns the same [slope, intercept].

    2.2 Polynomial fit

    Use NumPy's modern polynomial class. It rescales x internally, which keeps high-degree fits numerically stable.

    P = np.polynomial.Polynomial.fit(x, y_quad, deg=2)
print(P.convert().coef)        # coefficients in the ORIGINAL x variable, lowest power first

    [ 1.3665 -2.422   0.4416]       # c0, c1, c2  (true: 2, -3, 0.5)

    np.polyfit also works (note: highest power first). Evaluate with P(x_new).

    Warning: High-degree polynomial fits oscillate wildly outside the data range and can fit noise. If a physical model exists, use it (2.3) instead of piling on degrees.

    2.3 Custom function fit: curve_fit

    scipy.optimize.curve_fit fits any function of the form f(x, *params) using non-linear least squares. Here, a damped oscillator:

    from scipy.optimize import curve_fit

def damped(t, A, tau, w, phi):
    return A*np.exp(-t/tau)*np.cos(w*t + phi)

t = np.linspace(0, 10, 100)
y = damped(t, 2.0, 3.0, 2.0, 0.5) + rng.normal(0, 0.05, t.size)   # true A=2, tau=3, w=2, phi=0.5

popt, pcov = curve_fit(damped, t, y, p0=[1, 1, 1.8, 0])
perr = np.sqrt(np.diag(pcov))          # 1-sigma uncertainties
print(popt)
print(perr)

    [1.9694 3.076  2.0102 0.4816]
[0.0284 0.0609 0.0061 0.0125]

    Parameters worth knowing:

    Parameter What it does When to use it
    p0 Initial guess Always for oscillatory/non-linear models. Bad guesses are the #1 cause of failure
    bounds=(lower, upper) Restrict parameter ranges Keep amplitudes positive, phases in $[-\pi,\pi]$, etc.
    sigma Measurement uncertainties per point Weighted fits (you have error bars)
    absolute_sigma=True Treat sigma as real error bars, not relative weights Physics: when sigma are true uncertainties, so pcov is meaningful
    maxfev Max function evaluations Raise if you see "maximum number of calls reached"
    method 'lm' (default), 'trf', 'dogbox' 'trf'/'dogbox' are needed for bounds

    Weighted fit with real error bars:

    sig = 0.05 * np.ones_like(t)
popt, pcov = curve_fit(damped, t, y, p0=[1, 1, 1.8, 0], sigma=sig, absolute_sigma=True)
print(popt, np.sqrt(np.diag(pcov)))

    [1.9694 3.076  2.0102 0.4816] [0.0283 0.0607 0.0061 0.0125]

    2.4 Goodness of fit

    Never trust a fit without checking residuals. With known error bars, compute the reduced chi-squared; it should be close to 1.

    res  = y - damped(t, *popt)
chi2 = np.sum((res/sig)**2)
print(chi2 / (t.size - len(popt)))

    1.0057266238353433
    • $\chi^2_\nu \approx 1$: model and error bars are consistent.
    • $\chi^2_\nu \gg 1$: model is wrong or errors underestimated.
    • $\chi^2_\nu \ll 1$: errors overestimated (or overfitting).

    Also plot the residuals: structure in them (a trend, oscillation) means the model is missing something.

    2.5 When curve_fit is not enough

    scipy.optimize.least_squares is the lower-level engine. Use it when you need robust loss functions (loss='soft_l1' or 'huber') to down-weight outliers, or when your fit has vector residuals, such as fitting several datasets to shared parameters.

    3. Interpolation

    Fitting assumes a model; interpolation just passes a smooth function through your data. Typical uses: resampling experimental data, tabulated potentials, smoothing before differentiating.

    3.1 One dimension

    from scipy import interpolate as ip

xs = np.linspace(0, 2*np.pi, 8)
ys = np.sin(xs)

for kind in ['linear', 'cubic']:
    f = ip.interp1d(xs, ys, kind=kind)
    print(kind, f(1.0), "  exact:", np.sin(1.0))

    linear 0.8038608117306651   exact: 0.8414709848078965
cubic 0.8387508064447122   exact: 0.8414709848078965

    kind can be 'nearest', 'linear', 'quadratic', 'cubic'. (interp1d is considered legacy; for new code prefer the spline classes below, which do the same and more.)

    3.2 Cubic splines (the workhorse)

    CubicSpline gives you the function, its derivatives and its integral:

    cs = ip.CubicSpline(xs, ys)
print(cs(1.0))            # value
print(cs(1.0, 1))         # first derivative (exact: cos(1) = 0.5403)
print(cs.integrate(0, np.pi))   # exact: 2

    0.8387508064447122
0.5171038734973554
2.004683577965597

    Useful option: bc_type='periodic' for periodic data, 'natural' for zero curvature at the ends, 'clamped' to fix end slopes.

    3.3 Smoothing noisy data

    Interpolating noisy data reproduces the noise. Use a smoothing spline instead:

    spl = ip.UnivariateSpline(x, y_lin, s=len(x)*0.25)   # s ≈ N * sigma^2 is the classic choice
print(spl(5.0))

    13.357793410123822

    The smoothing factor s is the one knob: s=0 interpolates exactly; larger s gives a smoother curve.

    3.4 Higher dimensions

    Regular grid (e.g., a tabulated potential on a rectangular mesh):

    xg = np.linspace(0, 1, 5)
X, Y = np.meshgrid(xg, xg, indexing='ij')
Z = np.sin(X)*np.cos(Y)
g = ip.RegularGridInterpolator((xg, xg), Z, method='linear')
print(g([[0.3, 0.6]]), "  exact:", np.sin(.3)*np.cos(.6))

    [0.2407]   exact: 0.24390335148307188

    Scattered points (measurements at arbitrary positions): use griddata or RBFInterpolator.

    rng = np.random.default_rng(0)
pts  = rng.random((50, 2))
vals = np.sin(pts[:, 0])*np.cos(pts[:, 1])
print(ip.griddata(pts, vals, [(0.5, 0.5)], method='cubic'))     # exact: 0.4207
print(ip.RBFInterpolator(pts, vals)([[0.5, 0.5]]))

    [0.4207]
[0.4207]

    Rule of thumb: Interpolate inside the data range only. Extrapolation is unreliable (and interp1d raises an error unless you pass fill_value='extrapolate').

    4. Numerical differentiation

    Once you have data or a function, derivatives come next: velocities from positions, gradients of potentials, Jacobians for solvers.

    Finite differences approximate $f'(x) \approx \dfrac{f(x+h) - f(x-h)}{2h}$. The trade-off: small $h$ reduces truncation error but amplifies round-off error, so there is an optimal step, and noisy data makes the problem much worse.

    4.1 Derivatives of sampled data: np.gradient

    For data on a grid (no function available), np.gradient uses central differences inside and one-sided at the edges.

    x = np.linspace(0, 2*np.pi, 50)
y = np.sin(x)
h = x[1] - x[0]

dy = np.gradient(y, h)                      # or np.gradient(y, x) for non-uniform grids
print(dy[:3])
print(np.cos(x)[:3])
print(np.max(np.abs(dy[1:-1] - np.cos(x)[1:-1])))     # interior error

    [0.9973 0.9891 0.9646]
[1.     0.9918 0.9673]
0.002732537008859448

    Note that the first point is off by about 0.003: the edge uses a first-order formula. Fix it with edge_order=2:

    print(np.gradient(y, h, edge_order=2)[:2])

    [1.0054 0.9891]

    4.2 Derivatives of a function: scipy.differentiate

    For a Python function, scipy.differentiate.derivative (SciPy ≥ 1.15) picks step sizes adaptively and reports an error estimate. It replaces the old scipy.misc.derivative, which was removed.

    from scipy.differentiate import derivative

res = derivative(np.sin, np.pi/3)
print(res.df, "  exact:", np.cos(np.pi/3))
print(res.success)    # True if the requested tolerance was met

    0.49999999999998995   exact: 0.5000000000000001
True

    It is vectorised, so pass an array of points in one call:

    print(derivative(np.exp, np.array([0., 1., 2.])).df)

    [1.      2.71828 7.38906]

    Parameters worth tweaking:

    Parameter Meaning
    order Order of the finite-difference rule (default 8; use 2–4 for cheap, noisy functions)
    initial_step Starting step size (default 0.5; reduce for rapidly varying functions)
    step_direction 0 central (default), 1 forward-only, -1 backward-only. Use one-sided near domain edges, kinks, or singularities
    maxiter, atol, rtol Iteration limit and tolerances

    One-sided derivative of $|x|$ at its kink:

    print(derivative(np.abs, 0.0, step_direction=1).df)    # right-hand derivative → 1

    0.9999999999999865

    Higher derivatives: nest the call (cheap for low order, but accuracy degrades with each level).

    d2 = derivative(lambda t: derivative(np.sin, t).df, 1.0).df
print(d2, "  exact:", -np.sin(1.0))

    -0.8414709848079684   exact: -0.8414709848078965

    4.3 Gradients, Jacobians and Hessians of multivariable functions

    from scipy.differentiate import jacobian, hessian

# F: R^2 -> R^2  with  F = (x0^2 x1,  5 x0 + sin x1),  evaluated at (1, 2)
F = lambda x: np.array([x[0]**2*x[1], 5*x[0] + np.sin(x[1])])
print(jacobian(F, np.array([1., 2.])).df)

# scalar function -> Hessian
S = lambda x: x[0]**2*x[1] + x[1]**3
print(hessian(S, np.array([1., 2.])).ddf)

    [[ 4.      1.    ]
 [ 5.     -0.4161]]
[[ 4.  2.]
 [ 2. 12.]]

    4.4 A taste of findiff: a library dedicated to finite differences

    If derivatives on grids are central to your work (PDEs, field theory, lattice problems), look at the findiff package. It is built specifically around finite-difference operators in any number of dimensions, and lets you write differential operators almost the way you would on paper.

    pip install findiff

    import numpy as np
from findiff import Diff

x = np.linspace(0, 2*np.pi, 200)
dx = x[1] - x[0]

d_dx   = Diff(0, dx)              # first derivative along axis 0 (default: 2nd-order accurate)
d2_dx2 = Diff(0, dx, acc=4)**2    # second derivative, 4th-order accurate
df  = d_dx(np.sin(x))
d2f = d2_dx2(np.sin(x))

    Things that make it appealing for physics:

    • Accuracy control with a single acc= keyword, instead of hand-deriving stencils.
    • Operators compose algebraically. In 2D, the Laplacian is just Diff(0, dx)**2 + Diff(1, dy)**2, and mixed derivatives are Diff(0, dx) * Diff(1, dy).
    • Boundary handling: it automatically switches to one-sided stencils near the edges at the same order of accuracy, and supports periodic axes with periodic=True.
    • PDE/BVP solving with Dirichlet or Neumann boundary conditions through its PDE class, and findiff.coefficients(deriv, acc) to get raw stencil coefficients.

    4.5 Related: scikit-fdiff and numdifftools

    • scikit-fdiff (pip install scikit-fdiff, imported as skfdiff) is a slightly different beast: rather than differentiating arrays, it takes a PDE written as text (for example "k * (dxxT + dyyT)"), uses SymPy to build the finite-difference discretisation, and time-steps it with fast solvers. Handy for quickly prototyping transient PDEs (diffusion, advection, thin-film models). It is a small, niche project, so check that it still fits your Python version.
    • numdifftools offers Richardson-extrapolated derivatives, gradients and Hessians, a good alternative when scipy.differentiate isn't available.

    4.6 Practical advice

    • Noisy data: do not differentiate it directly. Smooth first (smoothing spline 3.3, or scipy.signal.savgol_filter(y, window_length, polyorder, deriv=1, delta=dx)).
    • Exact function available? Differentiate it symbolically with SymPy and lambdify it (Section 21). Exact derivatives beat any finite difference.
    • Big optimisation or ODE problems: supply analytic Jacobians when you can; it is usually the biggest speed-up available.

    5. Numerical integration

    5.1 One-dimensional integrals: quad

    scipy.integrate.quad is an adaptive routine (QUADPACK) and returns (value, error_estimate).

    from scipy import integrate as I

# Gaussian integral: exact sqrt(pi) = 1.7724538509055159
val, err = I.quad(lambda x: np.exp(-x**2), -np.inf, np.inf)
print(val, err)

    1.7724538509055159 1.420263678094492e-08

    Infinite limits work directly with np.inf. Integrable singularities are handled gracefully:

    print(I.quad(lambda x: 1/np.sqrt(x), 0, 1))     # exact 2

    (1.9999999999999984, 5.773159728050814e-15)

    Parameters worth tweaking:

    Parameter Use it for
    limit Max subintervals (default 50). Raise for oscillatory integrands
    points=[...] Locations of kinks/discontinuities inside the interval
    epsabs, epsrel Tolerances (defaults ~1.5e-8)
    weight='sin'/'cos', wvar=ω Fast, accurate oscillatory integrals $\int f(x)\sin(\omega x)\,dx$
    weight='cauchy', wvar=c Principal value integrals
    args=(...) Extra parameters passed to the integrand 
    # oscillatory: Si(50) = ∫0^50 sin(x)/x dx  (needs a larger limit)
print(I.quad(lambda x: np.sin(x)/x, 0, 50, limit=200))

# kink at x = 1
print(I.quad(lambda x: abs(x - 1), 0, 3, points=[1]))     # exact 2.5

    (1.5516170724859364, 3.1692223845247725e-10)
(2.5, 2.7755575615628914e-14)

    5.2 Multiple integrals

    # ∫0^1 ∫0^x  x*y dy dx = 1/8      (NOTE: dblquad's function takes (y, x), inner variable first)
print(I.dblquad(lambda y, x: x*y, 0, 1, 0, lambda x: x))

# ∫∫∫ over the unit cube of x*y*z = 1/8
print(I.nquad(lambda x, y, z: x*y*z, [[0, 1], [0, 1], [0, 1]]))

    (0.125, 5.515032205777789e-15)
(0.12499999999999999, 5.527033708952211e-15)

    Beyond ~3 dimensions, nested quad becomes very slow; switch to Monte Carlo (scipy.stats.qmc for quasi-random points) or to scipy.integrate.qmc_quad.

    5.3 Integrating sampled data

    When you only have samples, use trapezoid or simpson (needs an odd number of points for best results).

    x = np.linspace(0, np.pi, 11)
y = np.sin(x)
print(I.trapezoid(y, x))        # exact 2
print(I.simpson(y, x=x))
print(I.cumulative_trapezoid(y, x, initial=0)[:4])     # running integral

    1.9835235375094544
2.0001095173150043
[0.     0.0485 0.1894 0.4088]

    6. Ordinary differential equations

    Integration's big sibling: $\dot{\mathbf y} = \mathbf f(t,\mathbf y)$. Write any ODE as a first-order system; for example $\ddot x = -x$ becomes $y_0 = x,\; y_1 = \dot x$.

    6.1 Initial value problems: solve_ivp

    f = lambda t, y: [y[1], -y[0]]            # harmonic oscillator
sol = I.solve_ivp(f, [0, 10], [1, 0],
                  t_eval=np.linspace(0, 10, 5), rtol=1e-9, atol=1e-12)
print(sol.y[0])
print(np.cos(sol.t))
print(sol.status, sol.message)

    [ 1.     -0.8011  0.2837  0.3466 -0.8391]
[ 1.     -0.8011  0.2837  0.3466 -0.8391]
0 The solver successfully reached the end of the integration interval.

    Key parameters:

    Parameter Use it for
    method 'RK45' (default, non-stiff), 'DOP853' (high accuracy), 'Radau'/'BDF'/'LSODA' (stiff)
    rtol, atol Defaults (1e-3, 1e-6) are loose. For physics use rtol=1e-9, atol=1e-12 when accuracy matters
    t_eval Output times (does not change the internal step)
    dense_output=True Get a continuous solution sol.sol(t)
    events Stop or record when a condition is met (collisions, zero crossings)
    args Pass physical parameters to your function
    jac Analytic Jacobian (big speed-up for stiff problems)

    6.2 Stiff problems

    A problem is stiff when it contains widely separated time scales. Explicit methods like RK45 are forced into tiny steps; implicit methods are not:

    stiff = lambda t, y: -1000*(y - np.cos(t))
print(I.solve_ivp(stiff, [0, 1], [0], method='Radau').nfev)
print(I.solve_ivp(stiff, [0, 1], [0], method='RK45').nfev)

    100
2132

    If a solver crawls or nfev explodes, try method='Radau' or 'LSODA'.

    6.3 Events: detecting when something happens

    def hits_zero(t, y): return y[0]
hits_zero.terminal  = True      # stop integration there
hits_zero.direction = -1        # only when crossing downward

sol = I.solve_ivp(f, [0, 10], [1, 0], events=hits_zero, rtol=1e-9)
print(sol.t_events[0], "  exact π/2 =", np.pi/2)

    [1.5708]   exact π/2 = 1.5707963267948966

    6.4 Boundary value problems: solve_bvp

    For problems with conditions at both ends (for example, $y''=-y$, $y(0)=0$, $y(\pi/2)=1$):

    def fun(x, y): return np.vstack([y[1], -y[0]])
def bc(ya, yb): return np.array([ya[0], yb[0] - 1])      # residuals that must vanish

xm = np.linspace(0, np.pi/2, 5)
guess = np.zeros((2, xm.size))
sol = I.solve_bvp(fun, bc, xm, guess)
print(sol.status, sol.sol(np.pi/4)[0], np.sin(np.pi/4))

    0 0.70708860676209 0.7071067811865475

    status == 0 means it converged. A poor initial guess is the usual reason it does not.

    7. Linear algebra, eigenvalues and eigenvectors

    scipy.linalg is a superset of numpy.linalg (always built against BLAS/LAPACK) with extras such as expm, lu, generalized eigenproblems and more.

    7.1 Solving systems and basic operations

    from scipy import linalg as la

A = np.array([[2., 1.], [1., 3.]])

    7.4 Physics example: particle in a box (finite differences)

    9. Fourier transforms and signal basics

    9.1 The FFT

    For real signals, use rfft (half the work, half the output).

    from scipy import fft

N = 256
t = np.linspace(0, 1, N, endpoint=False)          # 1 second, sampling rate 256 Hz
s = np.sin(2*np.pi*50*t) + 0.5*np.sin(2*np.pi*80*t)

F    = fft.rfft(s)
freq = fft.rfftfreq(N, d=1/N)

print(freq[np.argsort(abs(F))[-2:]])     # two strongest frequencies (Hz)
print(2*abs(F)[[50, 80]]/N)              # recover amplitudes

    [80. 50.]
[1.  0.5]

    Practical rules: - Nyquist: the highest resolvable frequency is half the sampling rate. - Normalisation: to get true amplitudes from rfft, multiply by 2/N. - Windowing: if your signal doesn't contain a whole number of periods, apply a window (np.hanning(N) * s) to reduce spectral leakage. - Use fft.fft2/fftn for images and fields; fft.fftshift to centre zero frequency. - Spectral derivative: ifft(1j*k*fft(f)) is extremely accurate for smooth periodic functions.

    9.2 Beyond the FFT

    scipy.signal provides filtering (butter, filtfilt, savgol_filter), peak finding (find_peaks), spectrograms and power spectral density (welch), and convolution (fftconvolve). Worth knowing about even though we won't expand on it here.

    Part II – SymPy (symbolic)

    SymPy manipulates mathematics exactly: sqrt(2) stays sqrt(2), integrals come back as formulas, and equations are solved for symbols. Use it to derive, simplify and verify, then hand the result to NumPy/SciPy to evaluate.

    12. Getting started: symbols, assumptions, exact numbers

    12.1 Symbols and expressions

    12.2 Assumptions matter

    SymPy refuses to simplify things that are not true for all complex numbers. Tell it what you know:

    a = sp.symbols('a', positive=True)
x = sp.symbols('x')                      # generic complex symbol

print(sp.sqrt(x**2))      # can't simplify: depends on the sign of x
print(sp.sqrt(a**2))      # fine when a > 0

    sqrt(x**2)
a

    Common assumptions: real=True, positive=True, nonnegative=True, integer=True, nonzero=True. Declaring them is the single most effective way to get cleaner integrals and simplifications.

    12.3 Exact numbers vs floats

    15. Differential equations

    15.1 Ordinary differential equations

    Declare the unknown as an undefined Function, build the equation with Eq, then dsolve.

    x = sp.symbols('x')
f = sp.Function('f')

# f'' + 4 f = 0   (harmonic oscillator)
print(sp.dsolve(f(x).diff(x, 2) + 4*f(x), f(x)))

# f' = x f  with  f(0) = 1
print(sp.dsolve(f(x).diff(x) - x*f(x), f(x), ics={f(0): 1}))

# driven oscillator f'' + f = sin(2x),  f(0) = 0, f'(0) = 0
eq = f(x).diff(x, 2) + f(x) - sp.sin(2*x)
print(sp.dsolve(eq, f(x), ics={f(0): 0, f(x).diff(x).subs(x, 0): 0}))

    Eq(f(x), C1*sin(2*x) + C2*cos(2*x))
Eq(f(x), exp(x**2/2))
Eq(f(x), 2*sin(x)/3 - sin(2*x)/3)

    dsolve handles linear constant-coefficient equations, separable, exact, Bernoulli, many first-order types and some systems. It accepts hint='...' to pick a method (sp.classify_ode(eq, f(x)) lists what applies). Nonlinear equations such as the full pendulum $\ddot\theta = -\sin\theta$ have no closed form: go to solve_ivp.

    15.2 Partial differential equations

    sp.pdsolve exists but solves only a narrow class (mainly first-order and some separable equations). For the heat, wave and Laplace equations, the standard route is separation of variables by hand using SymPy for the pieces: Fourier series (Section 18), special functions, and integrals for coefficients.

    17. Laplace transform

    Converts ODEs into algebra, which is why it's a staple of circuits, control and damped systems.

    t = sp.symbols('t', positive=True)
s = sp.symbols('s')
a = sp.symbols('a', positive=True)

F = sp.laplace_transform(sp.exp(-a*t)*sp.sin(3*t), t, s, noconds=True)
print(F)
print(sp.inverse_laplace_transform(1/(s**2 + 1), s, t))

    3/((a + s)**2 + 9)
sin(t)
    • noconds=True drops the convergence conditions and returns only the transform.
    • If t is not declared positive, inverse transforms carry a Heaviside(t) factor (the function is zero for $t<0$), e.g. sin(t)*Heaviside(t). Declaring t positive, as above, removes it.
    • Partial fractions (sp.apart) before inverting often rescues a case where the inverse transform fails.

    Solving an ODE with Laplace: transform the equation, replace $\mathcal{L}{y'}= sY - y(0)$ and $\mathcal{L}{y''} = s^2Y - s\,y(0) - y'(0)$, solve the resulting algebraic equation for $Y(s)$ with sp.solve, then call inverse_laplace_transform.

    18. Fourier transform and Fourier series

    18.1 Fourier transform

    SymPy's default convention is $F(k)=\int f(x)\,e^{-2\pi i x k}\,dx$ (frequency $k$, not angular frequency). A Gaussian is its own transform in this convention.

    x, k = sp.symbols('x k', real=True)
a = sp.symbols('a', positive=True)

print(sp.fourier_transform(sp.exp(-sp.pi*x**2), x, k))
print(sp.fourier_transform(sp.exp(-a*x**2), x, k))

    exp(-pi*k**2)
sqrt(pi)*exp(-pi**2*k**2/a)/sqrt(a)

    If you want the physicist's convention with angular frequency $\omega$ (and different factors of $2\pi$), rescale the result by hand or compute the integral directly with sp.integrate. Always check the convention when you compare with a textbook. Also available: inverse_fourier_transform, sine_transform, cosine_transform.

    18.2 Fourier series

    x = sp.symbols('x')
fs = sp.fourier_series(x, (x, -sp.pi, sp.pi))      # sawtooth on (-π, π)
print(fs.truncate(3))                             # first 3 non-zero terms

    2*sin(x) - sin(2*x) + 2*sin(3*x)/3

    You can also work out the coefficients yourself:

    $$a_n = \frac{1}{\pi}\int_{-\pi}^{\pi} f(x)\cos(nx)\,dx, \qquad b_n = \frac{1}{\pi}\int_{-\pi}^{\pi} f(x)\sin(nx)\,dx$$

    n = sp.symbols('n', integer=True, positive=True)
bn = sp.integrate(x*sp.sin(n*x), (x, -sp.pi, sp.pi))/sp.pi
print(sp.simplify(bn))

    -2*(-1)**n/n

    Numerical counterpart for sampled data: scipy.fft (Section 9).

    sympy.physics.quantum also provides kets, bras, operators, commutators and tensor products for symbolic Dirac notation, and sympy.physics.matrices has Pauli and Dirac matrices (mdft, msigma, mgamma).

    20.3 Lagrangian mechanics: Euler-Lagrange equations

    Derive the equation of motion from a Lagrangian, then solve it numerically. Here: a simple pendulum with $L = \tfrac12 l^2\dot\theta^2 + g l\cos\theta$.

    from sympy.calculus.euler import euler_equations

t = sp.symbols('t')
g, l = sp.symbols('g l', positive=True)
th = sp.Function('th')

L = sp.Rational(1, 2)*l**2*th(t).diff(t)**2 + g*l*sp.cos(th(t))
eq = euler_equations(L, th(t), t)[0]
print(eq)
acc = sp.solve(eq.lhs, th(t).diff(t, 2))[0]
print(acc)

    Eq(-g*l*sin(th(t)) - l**2*Derivative(th(t), (t, 2)), 0)
-g*sin(th(t))/l

    The same technique works for a spring ($L=\tfrac12 m\dot q^2-\tfrac12kq^2$ gives $-kq-m\ddot q=0$), double pendulum, charged particle in fields, and so on. For many-body mechanical systems, look at sympy.physics.mechanics (LagrangesMethod, KanesMethod), which automates this bookkeeping.

    21. Bridging SymPy to NumPy/SciPy with lambdify

    This is the most useful trick in this entire guide. lambdify converts a SymPy expression into a fast numerical function (NumPy-vectorised by default when you ask for it).

    x = sp.symbols('x')
f = sp.lambdify(x, sp.sin(x)/x, 'numpy')
print(f(np.array([1.0, 2.0])))

    [0.84147098 0.45464871]

    21.1 Example: symbolic derivation → numerical integration

    Check a SymPy integral against quad:

    from scipy.integrate import quad

expr = sp.exp(-x**2)*sp.cos(3*x)
fnum = sp.lambdify(x, expr, 'numpy')

print(quad(fnum, -np.inf, np.inf)[0])
print(sp.integrate(expr, (x, -sp.oo, sp.oo)), "=", float(sp.sqrt(sp.pi)*sp.exp(-sp.Rational(9, 4))))

    21.2 Example: derive the pendulum, then simulate it

    Continuing from 20.3:

    from scipy.integrate import solve_ivp

a_func = sp.lambdify((th(t), g, l), acc, 'numpy')      # θ'' = a(θ, g, l)

sol = solve_ivp(lambda tt, Y: [Y[1], a_func(Y[0], 9.81, 1.0)],
                [0, 2], [1.0, 0.0], rtol=1e-8)
print(sol.y[0, -1])      # angle (rad) at t = 2 s, released from rest at 1 rad

    22. Limitations of SymPy

    SymPy is powerful, but knowing where it breaks saves hours of frustration.

    1. Speed. It is pure Python doing symbolic manipulation. Anything with thousands of terms (big symbolic matrices, high-order perturbation series, large sums) becomes very slow or runs out of memory. Substitute numbers early, use lambdify, or use a dedicated tool (Mathematica, Maple, FORM, Cadabra) for heavy algebra.

    2. No closed form ≠ SymPy's fault, but SymPy won't tell you which. Many integrals have no elementary antiderivative. SymPy either returns the integral unevaluated, or a special function, or occasionally a Meijer G-function that is correct but unhelpful.

    q = sp.symbols('q')
print(sp.integrate(sp.exp(-q**2)*sp.sin(q), q))      # gives back the integral unevaluated
print(sp.integrate(sp.sin(q**2), q))                 # Fresnel function: fine, closed form exists
print(sp.integrate(sp.exp(-q**2)*sp.cos(q**2), q))   # correct but opaque Meijer G output

    Integral(exp(-q**2)*sin(q), q)
3*sqrt(2)*sqrt(pi)*fresnels(sqrt(2)*q/sqrt(pi))*gamma(3/4)/(8*gamma(7/4))
-sqrt(2)*q*meijerg(((0, 1/4, 1/2, 3/4, 1, 9/8), (1/2,)), ((), (0, 1/8, 1/2)), 64/q**8)/(16*sqrt(pi))

    When this happens: check with scipy.integrate.quad for definite integrals, try changing variables or integrating by parts manually, or add assumptions (positive=True).

    3. solve cannot do transcendental equations that mix functions. Solving $\sin x = x/2$ raises NotImplementedError (multiple generators). Use nsolve (numerical, needs an initial guess) or scipy.optimize.brentq/root.

    4. Assumptions are easy to forget. Without positive=True, sqrt(x**2) stays sqrt(x**2) and Abs or re/im pieces creep into results (12.2). Many "SymPy can't simplify this" cases are really "SymPy doesn't know this is real".

    5. simplify is a heuristic. It does not guarantee the shortest or "nicest" form, may be slow, and the result can differ between versions. When it matters, apply targeted functions (trigsimp, factor, cancel, collect) and verify by checking sp.simplify(a - b) == 0, or numerically substituting random values.

    6. Equality is structural. a == b checks whether the expressions have the same form, not whether they are mathematically equal. Test with sp.simplify(a - b) == 0 or a.equals(b).

    7. Differential equation solvers are limited. dsolve covers many standard classes, but nonlinear, variable-coefficient or system cases frequently fail or return implicit solutions. pdsolve handles very few PDEs.

    8. Floating point creeping in. Writing 0.5 instead of sp.Rational(1, 2) converts exact expressions to approximate ones and breaks simplification. Use Rational or sp.S(1)/2.

    9. Matrices: size and symbolic eigenvalues. Exact eigenvalues of symbolic matrices beyond 4×4 (no general closed form for the characteristic polynomial roots) come back as unwieldy CRootOf objects or take forever. For numbers, use NumPy/SciPy.

    10. Python gotchas. ^ is XOR in Python (use **), 1/2 is a float (use sp.Rational), and sp.sin is not interchangeable with np.sin: np.sin(x) on a symbol will fail. See SymPy's "Gotchas" page.

    11. Not a proof assistant, and limited tensor support. Symbolic results can be subtly wrong in edge cases (branch cuts, singular points, conditional convergence). Treat output as a strong hint to verify, particularly for results you intend to publish. For heavy tensor algebra and general relativity, look at dedicated tools (Cadabra, einsteinpy, or the sympy.tensor module with patience).

    Rule of thumb: derive with SymPy, verify numerically with SciPy, and don't trust either blindly.

    23. Choosing the right tool: cheat sheet

    Task Numerical (SciPy) Symbolic (SymPy)
    Constants / units scipy.constants sympy.physics.units
    Fit data to a model curve_fit, least_squares, linregress derive the model, then lambdify
    Interpolate CubicSpline, RegularGridInterpolator, griddata sympy.polys.polyfuncs.interpolate (exact polynomials)
    Derivatives np.gradient, scipy.differentiate, findiff diff
    Integrals quad, dblquad, nquad, trapezoid, simpson integrate
    ODEs solve_ivp, solve_bvp dsolve (closed forms only)
    Eigenproblems eigh, eig, eigsh Matrix.eigenvals(), eigenvects()
    Roots brentq, root solve, solveset, nsolve
    Optimisation minimize, differential_evolution diff + solve for critical points
    Fourier scipy.fft fourier_transform, fourier_series
    Laplace transform (scipy.signal for LTI systems) laplace_transform
    Special functions scipy.special besselj, legendre, Ynm, ...
    Series / limits / sums — series, limit, summation

    Good habits that apply to everything above: 1. Test on a case with a known answer before trusting a result (we did this throughout this guide). 2. Check convergence: halve the step or tolerance and see if the answer changes. 3. Look at residuals and plots, not only at numbers. 4. Mind units and scaling: work in dimensionless variables when possible. 5. Read result objects: .success, .message, .status, error estimates.

    24. Conclusion

    SciPy and SymPy are complementary halves of a physicist's or mathematician's computational toolkit. SciPy gives you fast, battle-tested numerical routines (fitting, interpolation, differentiation, integration, ODEs, eigenproblems, optimisation, FFTs and special functions) that scale to real data and real simulations. SymPy gives you exact algebra, calculus, transforms and series for derivations, sanity checks and generating formulas you can read.

    The recurring pattern in this guide is: think symbolically, compute numerically. Derive the equation of motion with SymPy, lambdify it, integrate it with solve_ivp, fit its parameters with curve_fit, and compare against the exact limit you got from series. Whenever one tool hits its limits (SymPy with no closed form, SciPy with a poorly conditioned problem), the other usually provides the cross-check.

    From here, natural next steps are: plotting with Matplotlib, automatic differentiation and GPU numerics with JAX, PDE frameworks (findiff, FEniCS, py-pde), uncertainty-aware fitting (lmfit, iminuit, uncertainties), and Monte-Carlo and Bayesian tools (emcee, PyMC).
